# BLACK 복구 설계

사용자는 원본 소스가 없으며 남아 있는 DB 덤프·환경 백업과 이전 개발 대화를 토대로 Windows 서버에서 직원들이 쓰던 앱의 재구현을 요청했다. 원본 코드 복원이 아니라 호환 앱 재구현이다. 추가 설계 질의 대신 실행하도록 요청했다.

## 근거와 한계
대화 조회는 최근 5턴만 반환하며 hasMore=false다. 과거 이미지 7장의 바이너리와 초기 개발 메시지는 제공되지 않는다. 원본의 색상·배치·정확한 업무 규칙은 확인 불가. 확인된 화면은 로그인, 대시보드, 신규 등록, 명단 비교/결과, 일괄 등록, 대상자 검색/수정이다. 한국어 문구는 전달된 안내문에 맞춘다. 디자인은 BLACK 명칭에 맞춘 차콜 사이드바와 밝은 업무 화면으로 제안하여 구현한다.

## 구현
Node 22 이상, React/Vite, Express, PostgreSQL 18.4. 원본 User, RestrictedPerson, AuditLog 스키마와 ID를 유지한다. 내장 PostgreSQL은 loopback에서만 서비스하고 기존 DATABASE_URL은 별도 명시적 opt-in 없이 사용하지 않는다. 백업을 원본 DB에 덮어쓰지 않는다. 복구 스크립트는 빈 전용 DB만 대상으로 하고 SHA256·참조 무결성·건수를 검증한다. 업로드 백업과 환경 파일은 Git/배포 ZIP에 포함하지 않는다.

기존 bcrypt 계정과 암호화 전화번호의 호환성을 실제 백업으로 검증한다. 불명확한 암호화 형식은 추정 복호화 성공으로 간주하지 않는다. 기존 PHONE_ENCRYPTION_KEY는 보존한다. 신규 전화번호는 AES-256-GCM으로 암호화한다. 세션은 서버 저장, HttpOnly/SameSite 쿠키, CSRF, 로그인 속도 제한. 관리자만 사용자·감사로그 관리. 일반 직원은 대상자 조회·등록·수정 가능하며 삭제는 관리자만 가능하다는 보수적인 구현 판단을 문서화한다.

명단 비교는 정규화한 이름+전체 전화번호가 같으면 일치, 이름 또는 전화번호만 같으면 확인 필요, 둘 다 없으면 미등록. 자동으로 제한 결정을 내리거나 명단을 등록하지 않는다. XLSX/CSV/텍스트 미리보기, 최대 2000행, 비교 결과 XLSX 다운로드. 일괄 등록은 한 트랜잭션으로 처리하고 동일 이름·전화·사업 중복을 거부한다.

Windows 시작 배치 파일·설치/복구 안내와 자동 백업 명령 제공. 기존 https://gb-8234는 Windows 컴퓨터명/DNS/TLS 구성이 필요한 별도 운영 단계이며 현재 자동 복원됐다고 주장하지 않는다. 기본 접속은 localhost:8234, LAN 공개는 명시 설정 후 사용.

## 선택한 방법
원본 복구는 소스 부재로 불가. 백업 데이터에 호환되는 앱 재구현을 사용자가 선택했다. 클라우드 전용 새 서비스 대신 Windows에서 자체 실행할 수 있게 만들어 기존 운용 방식과 맞춘다.

## 검증
기존 덤프를 새로운 빈 DB에 복원하여 2계정/3대상자/126감사로그와 외래키를 확인한다. 비밀번호·전화번호 원문은 출력하지 않는다. 로그인, 권한, CSRF, 등록/수정/삭제, 중복 방지, 비교 분류, 엑셀 입출력, 트랜잭션, 백업·재복원, UI 주요 동선을 테스트한다. Windows 자체 실행은 Linux 검증과 구분한다.
