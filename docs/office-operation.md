# BLACK 사내 운영

이 문서는 Windows PC를 켜면 직원들이 `https://GB-8234/login`에 접속하는 구성을 설명합니다. 클라우드에서 Windows를 원격 조작한 상태가 아닙니다. 설치 파일을 실제 서버 PC와 직원 PC에서 실행하고 아래 검증까지 해야 운영 준비가 완료됩니다.

## 서버 PC 최초 설정

1. 기존 BLACK 서버의 PowerShell 창에서 **Ctrl+C**로 종료합니다. 다른 프로그램이나 DB 파일은 지우지 않습니다.
2. `BLACK-office-setup.zip`을 다운로드해 **별도 폴더**에 압축 해제합니다.
3. `SETUP-SERVER.cmd`를 실행하고 Windows 관리자 권한 요청을 승인합니다. 기본 앱 위치는 `다운로드\BLACK-recovery\BLACK`입니다. 다른 위치면 ZIP 안의 `SETUP-SERVER.ps1`에 `-AppPath "실제 앱 경로"`를 지정합니다.
4. 프로그램이 묻는 **직원 공통 비밀번호**에 사용자가 지정한 비밀번호를 입력합니다. 입력은 숨겨지며 코드/로그/GitHub에 기록하지 않습니다. 이름·이메일 5개만 대상으로 계정을 생성하거나 비밀번호를 변경합니다. 기존 다른 계정과 관리자 권한, 명단은 보존합니다. 기존 동일 직원 계정의 권한은 유지하며 새 직원은 일반 사용자입니다.
5. HTTPS 응답 확인과 백업 완료 문구가 나와야 합니다. 서버 PC에서 로그인합니다. 신규 계정은 햄맨/루피/조이/동동/체리의 기존 안내 이메일을 사용합니다.
6. **PC를 재부팅하고 Windows에 로그인하기 전에**, 아래 직원 PC에서 접속을 확인해야 전원만 켜도 되는 동작이 검증됩니다. Linux 테스트만으로 이 항목이 완료된 것은 아닙니다.

설정은 기존 앱 폴더에 코드만 갱신하며, 이전 코드는 `private/office-install-backups`에 보관합니다. DB 초기화·재복원·실행 중인 DB 파일 복사는 하지 않습니다. 계정 변경 전 암호화 안전 백업을 만듭니다.

## 직원 PC 최초 설정

서버 설정이 끝나면 기존 앱 폴더에 **`BLACK-staff-connect.zip`**이 만들어집니다. 이 파일만 직원들에게 전달합니다. 공개 서버 인증서와 주소만 들어 있으며 앱 데이터, 비밀번호, 암호화 키, 인증서 개인키는 포함하지 않습니다.

직원은 같은 사내망에서 ZIP을 풀고 `CLIENT-SETUP.cmd`를 실행합니다. hosts 주소 및 Windows 인증서 신뢰를 설정하므로 **최초 1회 관리자 권한**이 필요합니다. 설치기는 공개 인증서 SHA256을 검증하고 서버 응답을 확인한 뒤 브라우저를 엽니다. 이전 hosts 파일은 그 설정 폴더에 백업하며, 다른 호스트 항목은 보존합니다.

회사 공용 DNS가 있다면 IT 담당자가 `gb-8234`를 서버 주소로 등록할 수도 있습니다. 현재 설치기는 DNS 서버 설정이나 컴퓨터 이름을 바꾸지 않고 hosts 항목을 사용합니다.

## 운영 조건

- 서버 PC 전원이 켜져 있고 사내망에 연결되어 있어야 합니다. AC 전원에서 자동 절전/최대 절전을 끄며 배터리 설정은 바꾸지 않습니다.
- Windows 작업 스케줄러 `BLACK Office Server`는 부팅 20초 후, 현재 계정의 S4U 방식으로 실행합니다. Windows 암호를 저장하거나 자동 로그인을 설정하지 않습니다. 회사 보안 정책이 배치 로그온/S4U를 막으면 작업이 실행되지 않을 수 있으며 IT 담당자의 조치가 필요합니다. 대화형 로그인 시 실행으로 몰래 대체하지 않습니다.
- 서버는 443 HTTPS, DB는 127.0.0.1:15434만 사용합니다. 외부 공유기 포트 포워딩은 하지 않습니다. 방화벽은 Private/Domain의 LocalSubnet만 허용합니다. 공용 네트워크 프로필이나 다른 VLAN에서는 추가 확인이 필요합니다.
- **공유기/사내 DHCP에서 서버 PC의 현재 IP를 예약하세요.** hosts 방식은 서버 IP가 바뀌면 직원 설정 ZIP을 다시 만들어 적용해야 합니다. 예약되지 않은 주소로 영구 접속을 보장하지 않습니다.
- 자체 서명 인증서 만료는 1년입니다. 갱신 시 새 공개 인증서를 직원 PC에 다시 배포해야 합니다. 인증서 오류를 무시하거나 TLS 검증을 끄지 않습니다.
- 앱 폴더를 옮기거나 다운로드 정리로 삭제하지 마세요. 예약 작업이 설치된 절대 경로를 사용합니다. 이전하려면 정상 종료 후 별도 이전 절차가 필요합니다.

## 백업의 범위

**GitHub는 코드 백업입니다. 명단·비밀번호·환경 파일·TLS 개인키·DB는 GitHub에 넣지 않습니다.** ZIP으로 설치한 Windows 앱의 데이터가 GitHub에 자동 동기화되는 구조가 아닙니다. 이 작업에서 원격 커밋을 검증해 올린 소스가 GitHub 코드 백업이며, 이후 코드 변경도 별도 커밋/푸시가 필요합니다.

`BLACK Office Backup`은 부팅 2분 후와 매일 **17:30(Windows 현지 시간)**에 실행합니다. 꺼져 있을 때 놓친 실행은 다음 사용 가능 시점에 시도합니다. 백업 위치는 설정을 실행한 사용자의 **문서\BLACK-Backups**입니다. 폴더별로 암호화된 `black.black`, 복구용 원본 환경 키, 설정 사본, SHA256 검증값, 현재 앱 코드 ZIP을 저장합니다. 일관된 논리 트랜잭션으로 DB를 읽으며 실행 중인 data 폴더를 복사하지 않습니다. 기존 백업을 자동 삭제하지 않습니다.

**이 백업 폴더도 같은 PC에 있으므로 PC 전체 초기화·디스크 고장에 대한 외부 백업은 아닙니다.** `BLACK-Backups` 폴더를 외장 드라이브 또는 접근 제한된 별도 저장소에도 주기적으로 복사해야 합니다. 환경 키 파일을 잃으면 암호화된 전화번호와 백업을 읽을 수 없습니다. 비밀 키와 암호화 백업을 GitHub 공개 저장소에 올리지 않습니다.

## 실행·중지·상태 확인

관리자 PowerShell에서 기존 앱 폴더로 이동한 뒤 실행합니다.

```powershell
# 상태만 확인 — 비밀번호·키·세션 토큰은 출력하지 않음
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\windows\office-status.ps1

# 정상 종료하고 자동 재시작 일시 중지
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\windows\office-stop.ps1

# 자동 운영 다시 켜기
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\windows\office-start.ps1

# 즉시 추가 백업
Start-ScheduledTask -TaskName 'BLACK Office Backup'
```

정상 종료는 비공개 로컬 제어 파이프의 인증된 요청을 사용합니다. 네트워크에 종료 API를 노출하지 않습니다. 일시 중지를 먼저 하지 않으면 작업 스케줄러가 종료된 서버를 다시 시작할 수 있습니다. 일반 `npm start` 창으로 실행한 서버는 기존처럼 Ctrl+C를 사용합니다.

로그는 `private/office-logs`에 있습니다. 설정 실패 시 `office-status.ps1` 출력과 작업 스케줄러의 마지막 실행 결과로 진단합니다. `private` 전체나 키 파일을 직원에게 전달하지 마세요.

## 원본 키 파일 접근 오류

`EPERM ... private\BLACK.env.backup`은 원본 키 파일을 열지 못한 상태입니다. 키를 새로 만들거나 삭제하지 마세요. 수정 설치기는 파일 직접 권한과 폴더 상속 권한을 나누어 적용하고 읽기를 검사합니다. 여전히 실패하면 Windows ACL 또는 보안 프로그램 차단을 실제 PC에서 확인해야 합니다. 실패한 CLI의 종료 코드가 embedded runtime의 beforeExit 훅에서 0으로 바뀌던 문제도 수정했으며, 백업 파일 실재 확인 전에는 직원 계정 변경을 진행하지 않습니다.

Windows의 DB 시작은 PostgreSQL 공식 pg_ctl의 제한 토큰 실행 기능을 사용합니다. Node/설치기 권한과 별도로 PostgreSQL 프로세스에서 Administrators/Power Users 그룹 및 권한을 제거합니다. 임시 S4U 작업·설치기 파이프를 사용하지 않습니다. DB를 시작한 프로세스만 pg_ctl fast 종료를 수행하며 이미 실행 중인 동일 클러스터에 연결한 백업은 서버를 종료하지 않습니다.

## 기존 링크를 서버 PC만으로 복원

사용자 확인으로 초기화 전 PC 자체가 GB-8234였고 현재 이름 WINDOWS-71LEUCG, 이더넷 프로필 Public임이 드러났습니다. 직원 PC마다 hosts/신뢰를 설치하는 방식 대신 서버 PC의 원래 이름과 사내망 프로필을 복원합니다. `windows/restore-office-host.ps1`은 해당 서버의 이더넷만 Private으로 바꾸고 LocalSubnet에 TCP443, UDP137/5355를 허용합니다. NetBIOS 이름 조회를 켜고 예약 작업의 사용자 SID를 보존한 뒤 이름을 GB-8234로 예약 변경합니다. 도메인 가입 PC는 자동 이름 변경하지 않으며 재부팅도 자동 실행하지 않습니다. 기존 명단·직원 계정·TLS 파일은 바꾸지 않습니다. 이름 변경 후에는 저장한 작업을 닫고 서버 PC를 재부팅해야 합니다. 실제 직원 브라우저의 이름 해석 및 HTTPS 신뢰 결과는 재부팅 후 확인합니다. 이 절차에는 직원 PC 명령 실행이나 ZIP 배포가 없습니다.
