# BLACK 복구 앱

## 기존 설치에 원본 디자인 업데이트 적용

이미 앱이 실행 중이라면 `BLACK-design-update.zip`을 별도 폴더에 풀고 `UPDATE.cmd`를 실행한 후 브라우저에서 **Ctrl+F5**를 누릅니다. 다운로드의 기존 `BLACK-recovery/BLACK`을 우선 찾아 화면 파일과 프론트엔드 소스만 갱신하며, 이전 화면은 `.ui-backups`에 보관합니다. 데이터·환경 키·서버·의존성은 바꾸지 않습니다. 다시 설치하거나 DB를 재복원하지 않습니다. 직원 계정/활동 기록/비밀번호 변경은 상단 사용자 이름 메뉴에 있습니다.

기존 소스가 없는 상태에서 PostgreSQL 백업과 개발 대화에서 확인된 기능을 토대로 다시 만든 앱입니다. 기존 프로그램 코드의 복원이 아니며, 원본 이미지가 제공되지 않아 화면 디자인은 재구성했습니다.

## Windows에서 처음 실행하기

1. [Node.js](https://nodejs.org/)에서 **24 LTS, Windows x64**를 설치합니다. 설치 후 앱 ZIP을 `C:\BLACK` 같은 짧은 경로에 압축 해제합니다. OneDrive 동기화 폴더와 네트워크 드라이브는 피하세요.
2. `1-install.cmd`를 더블클릭합니다. PostgreSQL도 앱 폴더 안에 함께 설치됩니다. 별도 Docker나 Python 설치는 필요하지 않습니다. 설치된 `dist` 화면이 ZIP에 들어 있어 Windows에서 빌드하지 않아도 됩니다.
3. 앱 폴더 안에 `private` 폴더를 만들고 기존 백업 폴더에서 아래 **3개 파일을 복사**합니다. 원본은 그대로 보관하세요.
   - `BLACK.env.backup`
   - `black-2026-09-16T06-32-52-168Z.dump`
   - `backup-manifest.json`
4. `2-restore.cmd`를 실행합니다. **사용자 2명, 대상자 3건, 기록 126건** 복원이 확인되어야 합니다. 복원은 처음 한 번만 하며 이미 데이터가 있으면 덮어쓰지 않습니다.
5. `3-start.cmd`를 실행하고 브라우저에 **`http://127.0.0.1:8234/login`**을 입력합니다. 이것은 서버 컴퓨터 본인 확인용 주소이며 직원 컴퓨터용 주소가 아닙니다. 실행 창은 열어 두세요.
6. 기존 아이디와 비밀번호로 로그인합니다. 백업 당시 두 계정의 비밀번호 해시와 환경 백업의 초기 비밀번호가 일치하는 것을 확인했습니다. 기억나지 않으면 `BLACK.env.backup`을 본인 컴퓨터의 메모장으로 열어 `INITIAL_ADMIN_EMAIL`, `INITIAL_ADMIN_PASSWORD`를 확인하세요. 이 파일의 내용은 채팅이나 직원 단톡방에 보내지 마세요.

일반 PowerShell에서 직접 실행하려면 `npm.ps1` 실행정책 문제를 피하도록 `npm.cmd start`처럼 `npm.cmd`를 사용하세요. 제공한 CMD 파일은 실행정책 변경이 필요 없습니다.

## 직원 컴퓨터 접속과 예전 주소

위 1~6번은 서버 PC에서 동작을 확인하는 단계입니다. 예전 `https://gb-8234/login` 주소는 앱 설치만으로 돌아오지 않으며 **서버 이름 해석·HTTPS 인증서·방화벽** 설정이 필요합니다. 서버를 켜 놓고 같은 사내망에서 사용합니다. 인터넷 공유기의 포트 포워딩은 필요하지 않습니다.

### 선택: Windows HTTPS 설정

아래 스크립트는 Linux에서 실행 검증할 수 없는 Windows 전용 운영 보조 파일입니다. Windows에서 실제 실행 결과를 확인해야 합니다.

1. 앱을 종료하고 **관리자 PowerShell**을 엽니다. 다음을 실행합니다. 실행정책은 이 프로세스에만 적용됩니다.
   ```powershell
   cd C:\BLACK
   powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\lan-https.ps1
   ```
2. `3-start.cmd`로 다시 시작합니다. HTTPS 443 포트가 이미 다른 서비스에서 사용 중이면 기존 서비스를 종료하지 말고 충돌을 먼저 확인합니다.
3. 서버와 각 직원 PC에서 `gb-8234`가 서버의 사내 IPv4 주소로 해석되어야 합니다. 사내 DNS 담당자가 등록하는 방법을 권장합니다. 소규모 환경에서는 관리자 권한 메모장으로 `C:\Windows\System32\drivers\etc\hosts`에 `서버IPv4 gb-8234` 한 줄을 추가할 수 있습니다. 기존 내용은 보존합니다. DHCP 예약으로 서버 IP가 바뀌지 않게 합니다. 서버 IP는 서버 PC의 `ipconfig`에서 실제 사내망 어댑터의 IPv4를 확인합니다.
4. 스크립트가 만든 **공개 파일** `private\BLACK-server.cer`만 직원에게 전달합니다. 직원 PC에서 서버 관리자와 인증서 지문을 대조한 뒤 Windows의 신뢰할 수 있는 루트 인증 기관에 등록해야 합니다. 인증서 경고를 무시하고 로그인하지 마세요. `.pfx`, `tls.json`, `.env.backup`은 배포하지 않습니다.
5. 서버 PC 자신과 직원 PC에서 `https://gb-8234/login`에 접속해 로그인·검색을 확인합니다. 방화벽 허용은 Private 프로필의 LocalSubnet으로 한정되어 있습니다. 회사 네트워크 정책상 Public/Domain 프로필이면 IT 담당자에게 적절한 규칙을 요청합니다.

스크립트는 컴퓨터 이름과 hosts/DNS 및 다른 PC의 인증서 신뢰를 자동 변경하지 않습니다. 인증서는 1년 만료이므로 갱신해야 합니다. `.env` 또는 인증서가 이미 있으면 덮어쓰지 않고 중단합니다. 서버 인증서 개인키가 있는 `private`와 DB가 있는 `data`는 서버 관리자만 접근하도록 Windows 폴더 권한을 관리합니다.

수동 `.env`는 `BLACK_BIND_HOST=0.0.0.0`, `BLACK_PORT=443`, `BLACK_HTTPS=true`, `BLACK_PUBLIC_ORIGIN=https://gb-8234`입니다. `private/tls.pfx`와 UTF-8 `private/tls.json`(`password` 필드)이 필요합니다. 기본값은 본인 PC만 접속할 수 있는 loopback입니다. LAN 공개는 HTTPS 없이 시작할 수 없습니다.

## 제공 기능과 업무 규칙

- 대시보드: 활성 대상자 수, 이번 달 등록 수, 관리 사업 수, 최근 등록 내역.
- 대상자 목록: 이름·전화번호·사업명·사유·메모 검색, 사업·연도 필터, 페이지 이동.
- 신규 등록·수정: 이름, 전체 전화번호, 사업, 등록일, 사유, 메모. 수정 충돌·동일 이름/전화/사업 중복 방지.
- 명단 확인: XLSX/CSV/TSV/TXT 업로드 또는 텍스트 입력 → 미리보기 → 비교 → 결과 XLSX. 최대 2000명/10MB, XLSX 첫 시트만 읽습니다. 수식 셀은 거부합니다.
- 비교: 이름과 전체 전화번호 모두 같으면 **일치**, 둘 중 하나만 같으면 **확인 필요**, 둘 다 다르면 **미등록**. 삭제된 이력은 비교에서 제외합니다. 실제 업무 규칙을 확인할 수 없어 이 기준은 재구현 시 정한 규칙입니다. 명단 비교는 대상자를 자동 등록하지 않습니다.
- 일괄 등록: 입력한 명단 전체에 공통 사업·사유·날짜·메모 적용. 오류나 중복이 하나라도 있으면 전체 취소합니다.
- 관리자: 직원 추가·권한/비밀번호 변경·비활성화, 대상자 사유부 삭제, 활동 기록. 직원은 조회·등록·수정 가능. 원본 권한 정책이 없으므로 이 정책은 재구현의 보수적인 기본값입니다.
- 비밀번호 변경, 로그인 시도 제한, CSRF 방어, DB 저장 세션, HttpOnly/SameSite 쿠키. 세션 만료는 원본 환경 설정을 사용합니다.
- 전화번호는 원본 AES-256-GCM 데이터와 호환되며 신규 데이터도 암호화합니다. 목록에는 마스킹 번호를 표시하고 전체 번호 조회를 기록합니다. 감사 로그 화면에는 개인정보 원문 스냅샷을 표시하지 않습니다.

## 다시 잃어버리지 않도록 백업하기

`4-backup.cmd`를 실행합니다. 서버가 실행 중이어도 동일 로컬 DB에 접속해 일관된 트랜잭션 스냅샷을 만듭니다. `backups/날짜/` 안에 암호화된 `black.black`, 검증값 `manifest.json`, 원본 키 파일 `BLACK.env.backup`을 저장합니다. 이 폴더와 **앱 ZIP도 함께** 외장 드라이브/접근 제한된 저장소에 보관하세요. 키를 잃으면 전화번호와 새 백업을 복호화할 수 없습니다. 새 `.env` 설정이 있으면 별도로 보관하세요. 실행 중인 `data` 디렉터리를 단순 복사하는 방법은 사용하지 않습니다.

새 컴퓨터에서는 앱 설치 후 원본 키 파일을 `private/BLACK.env.backup`에 두고, 앱 폴더에서 다음을 실행합니다.

```powershell
npm.cmd run restore -- "D:\백업폴더\black.black"
```

데이터가 있는 곳에는 복원하지 않습니다. 기존 앱과 DB를 삭제하지 말고, 복원 검증용 앱을 별도 폴더와 별도 PC에서 준비하세요. 서로 다른 앱이 기본 DB 포트 15434를 동시에 쓰면 중단될 수 있습니다. HTTPS 인증서는 새 PC에서 새로 준비할 수 있습니다. 원본 DB URL은 사용하지 않으며 DB는 loopback 15434 포트만 엽니다.

## 개발 및 검증

```sh
npm ci
npm test
npm run build
npm run test:e2e
npm run dev
```

테스트는 임시 DB/가상 계정만 사용합니다. 실제 백업 파일은 Git과 배포 ZIP에 들어가지 않습니다. Linux에서는 npm에 포함된 Chromium으로 브라우저 테스트를 실행합니다. Windows에서 브라우저 테스트가 필요하면 `npx playwright install chromium`을 먼저 실행합니다.

현재 검증 범위: Linux의 PostgreSQL 18.4, 원본 덤프의 모든 필드가 독립 아카이브 리더와 일치, 사용자 2/대상자 3/감사로그 126 복원, 기존 암호/전화번호 호환, API 테스트와 브라우저 업무 동선. Windows 설치 및 사내 DNS/HTTPS는 사용자 PC에서 확인해야 합니다. 9월 16일 백업 이후 데이터는 이 백업으로 복구할 수 없습니다.
